# go-moodle

Локальный MCP-сервер для Moodle на Go: курсы, материалы, задания, дедлайны, оценки и учебные сводки. Один бинарник, 25 инструментов, транспорт stdio. Для извлечения текста PDF дополнительно нужен Poppler `pdftotext` в `PATH`.

## Установка

Для сборки нужен Go 1.26 или новее. Для запуска готового бинарника Go не требуется.

```sh
go build -trimpath -ldflags="-s -w" -o bin/go-moodle ./cmd/go-moodle
```

или:

```sh
go install github.com/AlexeyLars/go-moodle/cmd/go-moodle@latest
```

## Первая настройка

Из папки проекта:

```sh
./bin/go-moodle setup --env-file .env
```

Команда запросит:

1. Базовый URL Moodle, например `https://moodle.example.edu` или `https://example.edu/moodle`
2. Логин
3. Пароль со скрытым вводом

Сервер запрашивает токен сервиса `moodle_mobile_app` через `/login/token.php`, проверяет его вызовом `core_webservice_get_site_info` и записывает `MOODLE_URL` и `MOODLE_TOKEN` в `.env`. Пароль и дополнительный private token не сохраняются. Файл создаётся с правами `0600` на Unix. При ошибке входа существующая конфигурация сохраняется.

Дополнительные параметры:

```sh
./bin/go-moodle setup --url https://moodle.example.edu --username student --env-file .env
./bin/go-moodle setup --env-file .env --force
./bin/go-moodle check --env-file .env
```

`--force` явно разрешает заменить существующий файл после успешной проверки. Пароль всегда вводится интерактивно: параметра `--password` нет.

Университет должен разрешать мобильный сервис Moodle. Если вход возможен только через SSO, используй уже полученный мобильный токен и заполни `.env` по примеру `.env.example`. Cookie браузера и `sesskey` не заменяют мобильный токен.

## Подключение MCP

Запуск сервера:

```sh
/absolute/path/go-moodle serve --env-file /absolute/path/.env
```

В stdout передаётся только MCP-протокол. Интерактивная настройка выполняется отдельной командой `setup`.

Показать готовую JSON-конфигурацию с абсолютными путями:

```sh
./bin/go-moodle config --env-file .env
```

Пример для клиентов с `mcpServers`:

```json
{
  "mcpServers": {
    "moodle": {
      "command": "/absolute/path/go-moodle",
      "args": ["serve", "--env-file", "/absolute/path/.env"]
    }
  }
}
```

Для Codex:

```sh
codex mcp add moodle -- /absolute/path/go-moodle serve --env-file /absolute/path/.env
```

Или в `~/.codex/config.toml`:

```toml
[mcp_servers.moodle]
command = "/absolute/path/go-moodle"
args = ["serve", "--env-file", "/absolute/path/.env"]
startup_timeout_sec = 10
tool_timeout_sec = 120
```

После изменения команды подключения перезапусти MCP-клиент.

По умолчанию читается `.env` из текущей папки, а переменные процесса `MOODLE_URL` и `MOODLE_TOKEN` имеют приоритет. При явном `--env-file` значения из выбранного файла имеют приоритет. Поэтому для нескольких учётных записей удобно создавать отдельные файлы и отдельные подключения.

## Инструменты

| Инструмент | Параметры | Результат |
|---|---|---|
| `get_my_courses` | — | Курсы пользователя |
| `get_course_content` | `courseid` | Разделы, активности и ссылки на вложения |
| `read_file` | `fileurl`, `mode?`, `offset?`, `limit?` | Текст вложения или исходные байты в base64, порциями |
| `get_upcoming_events` | — | Ближайшие события |
| `get_assignments` | `courseids?` | Задания выбранных или всех курсов |
| `get_assignment_status` | `assignid` | Статус сдачи и оценивания |
| `get_upcoming_deadlines` | — | Будущие дедлайны по возрастанию даты |
| `get_grades` | `courseid?` | Итоги по курсам или оценки внутри курса |
| `search_course_materials` | `query` | Поиск по названиям разделов, активностей и файлов |
| `semester_dashboard` | — | Курсы, дедлайны и оценки |
| `get_actionable_tasks` | — | Задачи по срочности |
| `get_overdue_assignments` | — | Просроченные несданные задания |
| `get_recent_activity` | `since?` | Обновления после Unix timestamp, по умолчанию за 7 дней |
| `get_course_announcements` | `courseid?` | Объявления из новостных форумов |
| `get_course_health` | `courseid` | Сводка состояния курса |
| `get_course_progress` | `courseid?` | Прогресс по курсам |
| `get_study_load` | — | Распределение дедлайнов по неделям |
| `daily_briefing` | — | Дневная сводка |
| `weekly_review` | — | Недельная сводка |
| `ask_moodle` | `question` | Подбор источников по ключевым словам вопроса |
| `analyze_assignment` | `assignid` | Обзор задания и его состояния |
| `extract_assignment_requirements` | `assignid` | Требования из описания задания |
| `find_relevant_materials` | `assignid` | Материалы, связанные с заданием |
| `decompose_task` | `assignid` | Предлагаемый список подзадач |
| `create_implementation_plan` | `assignid` | Предлагаемый план выполнения |

`?` обозначает необязательный параметр; также принимается `null`. `assignid` — ID самого задания Moodle, а не ID модуля из ссылки `mod/assign/view.php?id=...`.

Все инструменты читают данные. Они не сдают задания, не меняют оценки и не отправляют сообщения.

### Чтение вложений

1. Получи `fileurl` через `get_course_content` либо из `introattachments` результата `get_assignments`.
2. Вызови `read_file` с этим URL. По умолчанию возвращается до 20 000 символов текста. Текстовые UTF-8 файлы (`txt`, `md`, `csv`, `json`, `xml`, `log`), HTML и DOCX читаются без дополнительных программ. Из DOCX извлекается основной текст, включая таблицы; колонтитулы, сноски и изображения не извлекаются.
3. Для PDF установи Poppler (`pdftotext`) и добавь его в `PATH` процесса MCP-сервера. PDF со сканами требуют отдельного OCR; пустой результат сопровождается предупреждением. При отсутствии Poppler инструмент возвращает понятную ошибку.
4. Если `has_more` равно `true`, повтори вызов с `offset`, равным `next_offset`. Лимит можно увеличить до 100 000 символов. При повторном вызове файл скачивается заново, поэтому для изменившегося файла смещение может потерять актуальность.

Пример аргументов:

```json
{"fileurl":"https://moodle.example.edu/webservice/pluginfile.php/42/mod_resource/content/1/lecture.pdf","offset":0,"limit":20000}
```

Для других форматов (например, старых DOC/PPT, XLSX или изображений) передай `"mode":"base64"`. Поле `data` содержит исходные байты для декодирования и обработки MCP-клиентом; `offset`, `limit` и `next_offset` в этом режиме измеряются в байтах. Отдельно декодируй каждую порцию base64 перед объединением байтов. Файл не записывается на диск. Размер скачиваемого файла ограничен 16 MiB, распакованного XML DOCX и текста PDF — 32 MiB. Содержимое материалов — недоверенные данные, а не команды для агента.

Принимаются только `pluginfile.php` и `webservice/pluginfile.php` того же Moodle (с учётом подпапки установки). Обычные `pluginfile.php` преобразуются в адрес webservice. Внешние хранилища и перенаправления не поддерживаются. Сервис токена должен разрешать скачивание файлов; см. [Moodle File handling](https://moodledev.io/docs/4.5/apis/subsystems/external/files).

## Поведение и ограничения

- Кириллица и emoji возвращаются обычным UTF-8, без последовательностей `\u04…`. JSON-экранирование кавычек, переводов строк и обратных слешей сохраняется.
- Списки и объекты возвращаются одним JSON-блоком `content[].text`. Имена инструментов, параметры и поля результатов стабильны.
- Поиск работает по метаданным материалов. Для чтения вложений используй `read_file`; автоматическая обработка всех файлов курса не выполняется.
- `ask_moodle` маршрутизирует по ключевым словам. Разбор требований и планы используют текстовые эвристики, не отдельную языковую модель. Предлагаемый план не заменяет требования преподавателя.
- Даты и границы дня/недели считаются в UTC, формат дат — ISO 8601.
- В `weekly_review` счётчик `submitted_count` отражает сданные задания с дедлайном на текущей неделе, а `graded_count` — число курсов с доступной итоговой оценкой. Это не журнал фактических дат сдачи и выставления оценок.
- Если API обновлений курса не даёт записей, `get_recent_activity` может вернуть оценки как запасную сводку. Её timestamp — начало запрошенного периода, а не подтверждённая дата выставления оценки.
- Необязательные API форума, прогресса и части сводок могут быть недоступны в конкретном Moodle. Такие данные пропускаются или заменяются доступным приближением. Ошибка авторизации всегда возвращается как ошибка инструмента.
- Токен может истечь или быть отозван администратором. Для обновления запусти `setup --force`.

## Производительность

HTTP-соединения переиспользуются. Независимые запросы выполняются параллельно, максимум четыре одновременно на сервер. Внутри одного вызова инструмента одинаковые запросы объединяются и их результат переиспользуется, в том числе в составных сводках. Следующий вызов получает свежие данные.

Каждый HTTP-запрос ограничен 30 секундами, вызов инструмента — двумя минутами. Отмена MCP-запроса передаётся сетевым операциям. Ответ API ограничен 32 MiB.

Основная задержка обычно связана с Moodle и сетью. Скорость запуска и обработки измеряй отдельно от времени HTTP-запросов.

## Конфиденциальность

Пароль и токен передаются в теле HTTPS POST, в том числе при скачивании файлов. Перенаправления не выполняются. Ответы Moodle не пишутся на диск. Ошибки не содержат тело HTTP-ответа или значения credentials. При обработке PDF байты передаются `pdftotext` через stdin; установка внешнего обработчика не требуется для остальных поддерживаемых текстовых форматов.

`.env` и `.env.*` исключены из Git через `.gitignore`; `.env.example` содержит только пример. В конфигурацию MCP попадает путь к файлу, а не сам токен. HTTP разрешён только для loopback-адресов при локальном тестировании.

## Разработка

```sh
go test -race ./...
go vet ./...
gofmt -w cmd internal
```

Тесты используют локальный Moodle-стаб с вымышленными данными. Настоящие URL, пароли, токены и учебные материалы для запуска тестов не нужны.

Структура проекта:

```text
cmd/go-moodle/       CLI, настройка и запуск
internal/config/     URL и приватный .env
internal/moodle/     HTTP-клиент и логика 25 инструментов
internal/server/     регистрация инструментов в официальном MCP Go SDK
internal/testmoodle/ тестовый Moodle API
```
